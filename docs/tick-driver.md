# Tick 驱动异动监控与并行验收

## 当前行为

实时入口同时订阅 ETF、主指数及辅助指数的 `tick_`，由本地 `TickMinutes` 聚合对齐分钟。供应商 `bar_` 保留作独立对账和缺口补齐，普通分钟与事件回放接口保持不变。

**生产默认仍为 `minute_driver: "provider"`**：正式告警继续由原供应商 bar 驱动；Tick 同时产生分钟内候选和影子检测结果。这样能够在尚无真实 Tick 对账证据时保留原告警结果。该版本没有自动晋升或自动切换数据源。

`minute_driver: "tick"` 已可运行：本地封闭分钟驱动同一个 `BurstDay` 检测器，供应商 bar 用于对账、补齐无法聚合的分钟。应先完成真实交易时段对账再启用生产主驱动。

## 计算口径

- `total_turnover` 是日内累计成交额。分钟额取对齐边界的累计额差值，不把每个 Tick 的累计额相加。
- 使用 `(开始时刻, 结束时刻]` 的对齐分钟，恰好 09:31:00 的 Tick 属于 09:31 分钟。首分钟以当日累计额为起点估计，包含开盘集合竞价累计；必须与实际供应商首分钟口径核对。
- 分钟结束后保留 **2 秒**接收宽限，由独立时钟推进封闭；不会依赖下一根 bar 到达。端点超过 **10 秒**没有有效快照时保留缺口，不填成零。以上是数据质量初始参数，不是修改放量阈值。
- 乱序 Tick 在未封闭区间内按市场时间插入；重复时间戳不重复计算。封闭分钟不因迟到 Tick 重新改写正式事件。累计额回退会标记对应分钟不可用。
- 午休不生成虚构分钟；13:00 可使用新鲜的上午收盘累计额作为起点，1/2/5/10 分钟检测窗口仍不能跨午休。14:57 后仍可聚合图表，但保持原检测器不参与正式放量判断的边界。
- 相同有效分钟输入仍复用原 `detect`/`BurstDay`：20/60 日 P75、全天中位数、倍数/占比阈值、预警/确认/极端、事件合并与升级均不改。

L1 Tick 是行情快照，不等于逐笔成交。两个快照之间的成交无法精确拆到分钟边界两侧，所以本地分钟**不能天然保证等于供应商 bar**。对账完成前不允许以“公式没变”替代数据一致性验收。

## 分钟内候选

对当前对齐分钟的已发生成交额，加上此前完整分钟，在数组副本上调用原检测公式。分母仍使用完整历史同窗 P75 和全天中位数，不按秒数缩小分母，也不改为任意连续 120/300/600 秒窗口。

- 预警/确认/极端的候选均标注“未确认、不播报”，单列展示。
- 候选不会改变正式检测器的值、事件、合并状态或影子中位数命中，不加入正式事件列表，不触发语音。
- 行情变陈旧或当前分钟结束后候选会移除；只有封闭分钟经正式检测通过才成为正式事件。
- 候选属于提前观察，可能因数据差异或后续补齐而未获正式确认；不能称为提前确定了交易主体。

## 配置与归档隔离

默认 `config/etf-burst.json`：

```json
{"amount_window_quantile": 0.75, "minute_driver": "provider"}
```

独立 Tick 主驱动测试可保存 `.local/etf-burst-tick.json`：

```json
{"amount_window_quantile": 0.75, "minute_driver": "tick"}
```

在独立测试终端为采集器和网页设置一致的路径：

```powershell
$env:ETF_BURST_CONFIG = '.local/etf-burst-tick.json'
$env:ETF_BURST_DIR = 'data/private/etf-burst-tick'
$env:FTSHARE_LIVE_CACHE_FILE = 'data/private/rqdata-tick-live.json'
# 启动方式不变；两者分别在终端运行，不创建计划任务
& .\scripts\python-backend.ps1 -Mode live -Arguments @('--watch')
# 另一个终端设置相同环境后启动 web；已有实例需先正常停止或使用独立 PORT
& .\scripts\python-backend.ps1 web
```

同一归档目录中，当天已有另一分钟驱动写入时，采集器拒绝覆盖，要求使用独立 `ETF_BURST_DIR`。不要让两个采集进程写同一缓存。并行对账本身在一个采集器中完成，不需要为了对账再开一个采集器。

## 对账和数据质量

事件 JSON 的 `tick_monitor` 和网页“Tick 与供应商 bar 对账”展示：

- 实际正式分钟驱动 `minute_driver`；已比较分钟格数 `compared`；金额差异总数 `mismatched`。
- 差异明细 `differences` 仅保留最新 20 条，完整差异总数仍保留；容差为 `max(0.01元, abs(provider_amount) × 1e-9)`。
- Tick 缺口、供应商补齐量、未补齐量及迟到/重复/累计回退拒绝数。缺口含采集器启动前未收到 Tick 的时段，不等于全部是网络丢包。
- 两个检测器的事件数，以及在双方共同已完成分钟内的事件 ID/等级差异 `event_mismatches`，明细保留最新 20 条，避免正常 2 秒封闭时差直接冒充漏报。Tick 检测器可能使用已标记的 bar 补齐，不能把这些补齐分钟当成独立 Tick 对账样本。

出现金额差异时记录差异，不自动覆盖本地封闭分钟，不倒改已发出的事件。Tick 模式中的 bar 补齐事件保留 `recovered` 标记并遵循原有“不补播”规则。

## Tick 数据回放

`burst-replay --burst-input` 保留原成交额分钟导入；输入额外含 `ticks` 时使用同一个 Tick 聚合器重放。`1m`/`1d` 仍用于构造截至前一交易日的基准，不能省略历史样本而冒充基准充分。

```json
{
  "schema_version": 2,
  "metric": "turnover",
  "unit": "CNY",
  "1m": [],
  "1d": [],
  "ticks": [
    ["510050.SH", "2026-11-13T09:30:58+08:00", "2026-11-13T09:30:58.100+08:00", 1.1, 1000000]
  ]
}
```

五列依次为代码、市场时间、接收时间、最新价、日累计成交额。时间必须包含时区；输入必须按接收顺序保存，不按市场时间重排迟到数据。上例只是结构示意，缺历史和完整当日 Tick，不能用于完整性验收。

```powershell
& .\scripts\python-backend.ps1 -Mode burst-replay -Arguments @(
  '--burst-input=.local/turnover-ticks.json', '--end=2026-11-13',
  '--burst-dir=.local/tick-replay', '--burst-config=.local/etf-burst-tick.json')
```

输出仍为 `replay/YYYY-MM-DD.json`，含正式事件、接收覆盖、拒绝统计和独立 `candidate_history`。网页按回放时点过滤历史 Tick 候选；普通分钟回放不会伪造分钟内候选，回放不播报。正式事件展示仍以分钟为粒度，不能由此推断真实通知到达秒数。

当前采集器不归档所有原始 Tick；精确 Tick 重放需自行保存带接收时间的输入。不要用历史 Tick 的市场时间伪造实际接收时间并称为实盘时延验收。

## 测试证据及切换条件

最终回归：Python **55 项通过**，Node **95 项通过**；浏览器验证通过候选展示/正式事件与语音隔离、历史候选时点过滤、九张原图、实时推送和断线读取回退。JavaScript 语法、文档目标与 `git diff --check` 通过。

- 自动回归覆盖：累计差分、整分钟边界、2 秒封闭、10 秒陈旧边界、午休、指数无成交额、重复/乱序/迟到/回退、候选不改正式状态、Tick 单独确认、供应商补齐、防止同日跨驱动覆盖、原分钟回放及 Tick CLI。
- 同一组整数分钟输入下，Tick 回放与原 bar 检测器的正式事件、升级和中位数影子结果逐项相同。
- 本地缓存三日、当前篮子重叠的 16 只 ETF：把原分钟额构造成累计快照再重放，正式事件分别 **20 / 31 / 7**，按事件 ID 对齐后的首报分钟、最新分钟、等级、峰值窗口一致。多标的同一时刻触发的数组顺序不作为规则差异。证据在 `.local/tick-driver-validation/results.json`。
- 上述累计快照是从分钟数据**合成**，不是实际历史 Tick；当前篮子另外 4 只没有补齐。本次证据不足以证明真实 Tick 和供应商分钟完全一致。
- 浏览器验收检查：候选可见、正式事件数不因候选增加、开启语音后候选不额外播报，以及九张原图、SSE 回退、历史回放。

生产切换前应取得真实 Tick 与供应商 bar 的同日记录，覆盖开盘、午休、重连及收盘，检查逐只逐分钟金额、候选与正式首报时刻、事件等级与漏报。先解释所有差异，再决定是否启用 `minute_driver: "tick"`；没有配置为自动切换，也没有假定已完成真实账户验收。
