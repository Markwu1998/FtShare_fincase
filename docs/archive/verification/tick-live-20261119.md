# Tick 行情链路、计算修复与验收（2026-11-19）

> 后续已增加 Tick 本地分钟聚合、候选及双链路对账，当前驱动模式和切换边界见 [Tick 驱动异动监控](../../reference/tick-driver.md)。本文保留上一批 UI 链路优化的验收记录。

## 实现范围

在 `dev_home` 合入 `dev_ebscn` 后实施本次优化，沿用 Python 采集器、FastAPI、共享文件缓存和原有网页。没有注册本机计划任务，也没有推送远程。原有本地 `package-lock.json` 修改保留。

此次保持成交额 P75 和分钟放量阈值不变，优化数据正确性、发布和展示链路。成交额阈值仍须用独立样本校准，不能把旧成交量回放结论当作当前版本效果。

## 实时与分钟的边界

```text
RQData LiveMarketDataClient
  tick_ -> 时间去重/累计额回退检查 -> 最新价、当日累计额、盘口、指数报价
  bar_  -> 完整分钟序列 -> 分钟图、20/60 日基准比较、逐 ETF 放量确认
                 |
        Python 共享缓存（原子替换，约每秒合并发布）
                 |
        FastAPI /api/live/stream（SSE，每秒检查新版本）
                 |
        网页即时更新报价、概览、单只 ETF 卡片
        分钟数据改变时才更新分钟图与分钟信号
```

- 原页面每约 60 秒才读取行情。现在 Tick 报价不再等待下一个 bar 或下一次分钟轮询，首个完整分钟之前也可展示已经收到的报价。
- 不承诺逐笔到达即逐笔绘制：采集与 SSE 各有约 1 秒合并周期，上游推送频率和网络还会增加延迟。该版本适合约秒级观测，真实端到端时延须实测。
- Tick 更新最新价、累计成交额、买一/卖一、参考溢价、上证综指报价和逐只时间；表中滞后 90 秒的标的在交易时段标记滞后。
- `total_turnover` 是当日累计金额，不能直接写成当前分钟成交额。当前分钟图和 P75 信号始终使用已结束 bar，不把未结束分钟混入历史基准。
- 报价不齐时总成交额留空，已收到的单只报价可展示；分钟不齐时保留缺口。某只 ETF 有新 tick 不代表其他 19 只也刚更新，因此保留逐只行情时间。
- IOPV 数值是否变化不能证明其真实更新时间。页面溢价明确标注时效待核，作为参考，不能据此认定转溢信号已经过实盘校验。
- RQData 文档说明实时分钟线可能因延迟 tick 而与盘后历史清洗结果不同。实盘事件与盘后回放保留不同目录，不把回放结果视为当时已送达的告警。

## 接口与回放

| 接口 | 用途 |
|---|---|
| `/api/live/stream?realtime_source=rqdata` | Tick 行情 SSE，事件 `live`；无有效当日数据发 `unavailable`；不依赖日频源就绪，不发送历史回放作为实时行情 |
| `/api/live` | 一次性读缓存；不接通上游；SSE 不可用时页面每 2 秒读取 |
| `/api/etf-burst/stream` | 完整分钟产生的预警/确认/极端事件，与 Tick UI 流独立 |
| `/api/etf-burst?date=YYYY-MM-DD` | 历史事件回放；历史日期继续禁用播报 |
| `/api/board` | 日频快照，支持 ETag / If-None-Match；未变化可返回 304 |

页面日频检查继续按原周期运行，不随每个 Tick 重取或重绘整份历史。SSE 自动重连时按当前最新状态恢复，不保存浏览器断线期间每一笔 Tick；需要逐笔回放时仍须另外归档完整 Tick。

事件归档和离线导出必须为 `schema_version=2, metric="turnover", unit="CNY"`。新事件还记录规则版本、分位参数、篮子 hash、基准截止日和分钟接收覆盖。旧无版本/成交量归档不按亿元显示，保留原文件并从可核实的成交额数据重新生成。

```json
{
  "schema_version": 2,
  "metric": "turnover",
  "unit": "CNY",
  "1m": [["510050.SH", "2026-11-13", "09:31", 1000000]],
  "1d": [["510050.SH", "2026-11-13", "15:00", 240000000]]
}
```

该 JSON 仅示意结构，不能作为具备 20/60 日完整历史的有效回放样本。既有 `live --replay` 和独立 `-ReplayCache` 启动方式保留，参见 [Python 后端](../../getting-started/live-setup.md)。

## 审查问题处理

| 问题 | 本次处理及边界 |
|---|---|
| DDB 折算产生假净申购 | 按 `SPLIT_RATIO` 累乘调整因子，交给共同公式；对可用的元单位 `NET_INFLOW` 对账，容差为 max(0.01元, abs(NET_INFLOW)×1e-9)。明确折算但无对账值、缺基准或结果冲突时拒绝构建；折算比和对账值均缺失的日期保留净申赎缺口，不把结果直接填零 |
| DDB 净值缺失 | 历史缺 NAV 时按 `SECURITY_ID`、`END_DATE` 关联 `fund_nav.NAV`；不替换已有份额表 NAV，不填造份额。目标日核心就绪检查仍要求份额表有效 NAV，采用保守阻断 |
| DDB 周末/缺数检查 | 用已观察到的上证指数交易日确定目标，再逐只检查目标日价格、成交额、份额和 NAV。指数源自身整日漏数仍需独立交易日历进一步识别，未声称该问题彻底解决 |
| 重复 DDB 日记录 | 行情、份额、指数、回退 NAV 重复主键拒绝构建，防止重复折算或覆盖 |
| 实时 ready 缓存 | 纳入实时文件版本、日期和时间桶，跨日/回放不冒充当前实时源；实际新鲜度以 `/api/live` 和逐只时间为准 |
| 日频晚披露阻断实时页 | `/api/live` 与日频就绪解耦；有效 RQData 历史可继续读取并提示待更新，DDB 未就绪仍禁止切换 |
| 更新脚本误报成功 | 显式检查每步 `$LASTEXITCODE`；必需源失败保持非零返回，独立拥挤度继续运行；可选 DDB 失败作为降级记录 |
| 旧量/额混用 | 后端、导入器与前端校验版本和单位，移除 volume→亿元的兼容展示 |

上述 DDB 逻辑有合成反例覆盖，尚未连接生产 DDB 全量对账，也未实现 `fund_div` 独立交叉核对。字段定义仍以部署环境为准。

## 性能

- 用滚动和替代重复的窗口切片求和，保留缺分钟和午休边界；测试按随机缺失样本逐点对比旧定义。浮点结果按数值容差验证，不承诺字节级相同。
- 每日分钟/指数基准缓存于 `ETF_BURST_DIR/baselines/YYYY-MM-DD.json`。身份包含日期、基准截止日、标的、分位数和规则版本；不匹配则重建。测试确认命中缓存不查询历史，修改分位数会重新查询。该缓存不自动发现上游同日历史修订，需删除当日基准缓存并重启采集器以重建。
- Tick 只更新报价行和证据；未变化不重复写行情快照，完整分钟序列未变化不重建分钟快照/图表。
- 消息队列满时不阻塞回调 5 秒，触发重连并补分钟；不能重建丢失的逐笔盘口，不能据此声称 Tick 零丢失。
- DDB 大表转换改用批量记录遍历，NAV 回退使用预先构建的日期集合；未引入分布式基础设施。

同一台机器、20 ETF × 60 日 × 240 分钟常量合成样本：基准构建从初审中位约 **3.18秒** 降至本次约 **1.21秒**；单日回放（含基准）本次约 **1.71秒**。该测量不含上游取数和生产负载，不代表实盘告警延迟。

## 使用与生产验收

继续分别启动网页 `scripts/python-backend.ps1 web` 和采集器 `scripts/python-backend.ps1 -Mode live -Arguments @('--watch')`；已有服务需重启后加载 Python 改动，浏览器刷新以加载新脚本。确认 `DATA_MODE=live`；默认端口 8080，可由 `.env` 覆盖。

生产前在获准登录的机器上：确认 SSE 无代理缓冲；逐只检查报价时间推进；测量市场时间、接收时间、发布时间及页面到达时间；在首分钟、午休、重连、收盘和跨日分别验证；补齐当前 20 只历史并重新回放成交额阈值。该工作不通过在本机创建计划任务代替。
