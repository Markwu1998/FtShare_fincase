# Tick 驱动异动监控与并行验收

## 股指期货同窗观测

`config/etf-burst.json` 默认启用 `futures_evidence`。采集器查询当天 IF、IH、IC、IM 实际挂牌的四个期限，独立订阅 RQData Level 1 Tick。ETF 达到原规则二级及以上后，约在窗口结束 6 秒后生成对应期货观测。界面每个 ETF 事件显示最近一次确认窗口，日志保留每一次。相同指数的多个 ETF 可以引用重叠期货窗口，跨 ETF 汇总期货金额须先按合约和时间去重。

ETF 窗口展示成交金额和分钟线成交股数。期货净增仓名义额按各合约的「结束持仓减起始持仓 × 起始价格 × 合约乘数」累计，包含有符号减仓，四个合约的窗口端点均齐备时才展示整体值。界面还显示起止时间、合约数量、方向可分类成交额占比及可用的期货相对现货收益变化。

相邻 Tick 的累计成交手数和成交额分别差分。若区间均价和最新价均不高于上一帧买一，将该区间成交额计入**主动卖成交额估算**。若两者均不低于卖一，计为可分类的买侧区间。锁价、盘口缺失、跨窗口起点、快照间隔超过 10 秒或方向不清的区间不归类。累计数倒退、持仓变动超过区间成交手数、端点超过 10 秒未更新时，对应合约窗口标为缺测。

**卖侧增仓估算额**只计算判为卖侧且持仓上升的区间，计算式为「正增仓手数 × 区间成交均价 × 合约乘数」。同窗整体净增仓且有正的卖侧增仓估算值时，界面提示「同窗增仓伴卖侧迹象」。快照可能合并多个方向和开平仓交易，正增仓与主动卖在同一快照间隔共现无法确认为同一笔卖开，更无法识别套保或交易账户。

结果写入当日私有 SQLite 日志的 `futures_evidence`，包括 ETF 事件 ID、窗口、股数和成交额、估算值、覆盖率、合约及期限分布。用于复算的窗口期货快照保存为 `futures_tick`，带行情和接收时间，可通过现有日志接口按类型和代码分页。窗口重叠时快照去重。盘中重启前尚未收到或已超出内存窗口的数据可能缺测。历史分钟回放没有期货 Tick 证据时显示缺失。

`futures-l1-window-v2` 在窗口合计和每个合约中保存 `directions`，分别记录卖侧、买侧、未分类区间的成交额、持仓增加和减少手数、增加额、减少额及净变化额。持仓金额按各合约窗口期初价和乘数计算，持仓减少额为负数，三区间净变化之和可与全窗口净增仓名义额对账。卖侧增仓估算额仍按相应区间成交均价计算。卖侧区间持仓减少可以用来定位疑似卖平样本，快照无法识别个别成交的开平仓方向。

异动雷达的「期货金额口径」默认选主动卖成交额估算。切换后，事件行、期货金额与 ETF 同窗成交额之比，以及合约明细同步更新。下拉选择仅影响显示，日志始终保存所有字段。四期限不齐时，分类合计缺失，已有合约可单独查看。旧归档保留原字段，新字段缺失显示横线。

`GET /api/etf-burst/journal?date=YYYY-MM-DD&kind=futures_evidence` 查询窗口证据。将 `kind` 换为 `futures_tick`，并以 `symbol=IF2612` 等实际合约筛选，可查询保存的 Tick。数据字段见 [RQData 行情说明](https://www.ricequant.com/doc/rqdata/python/generic-api.html)。

## 当前行为

实时入口同时订阅 ETF、主指数及辅助指数的 `tick_`，由本地 `TickMinutes` 聚合对齐分钟。供应商 `bar_` 保留作独立对账和缺口补齐，普通分钟与事件回放接口保持不变。

**生产默认仍为 `minute_driver: "provider"`**：正式告警继续由原供应商 bar 驱动；Tick 同时产生分钟内候选、30/60 秒持续性候选和影子检测结果。历史 Tick 对账与真实订阅验收分别记录，没有自动晋升或自动切换数据源。

`minute_driver: "tick"` 已可运行：本地封闭分钟驱动同一个 `BurstDay` 检测器，供应商 bar 用于对账、补齐无法聚合的分钟。应先完成真实交易时段对账再启用生产主驱动。

## 计算口径

- `total_turnover` 是日内累计成交额。分钟额取对齐边界的累计额差值，不把每个 Tick 的累计额相加。
- 当前实时聚合采用 `provider-v2`：普通分钟边界使用严格早于边界的最后快照，恰好 09:31:00 的 Tick 归入下一分钟。11:30 和 15:00 收盘端点可取结束后 5 秒以内的收盘快照；首分钟包含集合竞价累计。
- 普通分钟结束后保留 **2 秒**接收宽限；收盘分钟保留 **6 秒**，再封闭结束后 5 秒内的收盘快照。端点超过 **10 秒**没有有效快照时保留缺口，不填成零，不会依赖下一根 bar 到达。以上是数据质量参数，不是放量阈值。
- 乱序 Tick 在未封闭区间内按市场时间插入；重复时间戳不重复计算。封闭分钟不因迟到 Tick 重新改写正式事件。累计额回退会标记对应分钟不可用。
- 午休不生成虚构分钟；13:00 可使用已封闭的上午收盘累计额作为起点。午休的后续心跳不会遮蔽该有效锚点。1/2/5/10 分钟检测窗口不跨午休；14:57 后可聚合图表，保持原正式检测截止边界。
- 相同有效分钟输入仍复用原 `detect`/`BurstDay`：20/60 日 P75、全天中位数、倍数/占比阈值、预警/确认/极端、事件合并与升级均不改。

L1 Tick 是行情快照，不等于逐笔成交。两个快照之间的成交无法精确拆到分钟边界两侧，所以本地分钟**不能天然保证等于供应商 bar**。对账完成前不允许以“公式没变”替代数据一致性验收。

## 分钟内候选

对当前对齐分钟的已发生成交额，加上此前完整分钟，在数组副本上调用原检测公式。分母仍使用完整历史同窗 P75 和全天中位数，不按秒数缩小分母，也不改为任意连续 120/300/600 秒窗口。

- 预警/确认/极端的候选均标注“未确认、不播报”，单列展示。
- 候选不会改变正式检测器的值、事件、合并状态或影子中位数命中，不加入正式事件列表，不触发语音。
- 行情变陈旧或当前分钟结束后候选会移除；只有封闭分钟经正式检测通过才成为正式事件。
- 候选属于提前观察，可能因数据差异或后续补齐而未获正式确认；不能称为提前确定了交易主体。

## 配置与归档隔离

默认 `config/etf-burst.json`：

```json
{"amount_window_quantile": 0.75, "minute_driver": "provider", "futures_evidence": true}
```

独立 Tick 主驱动测试可保存 `.local/etf-burst-tick.json`：

```json
{"amount_window_quantile": 0.75, "minute_driver": "tick"}
```

在独立测试终端为采集器和网页设置一致的路径：

```powershell
$env:ETF_BURST_CONFIG = '.local/etf-burst-tick.json'
$env:ETF_BURST_DIR = 'data/private/etf-burst-tick'
$env:FTSHARE_LIVE_CACHE_FILE = 'data/private/rqdata-tick-live.json'
# 启动方式不变；两者分别在终端运行，不创建计划任务
& .\scripts\python-backend.ps1 -Mode live -Arguments @('--watch')
# 另一个终端设置相同环境后启动 web；已有实例需先正常停止或使用独立 PORT
& .\scripts\python-backend.ps1 web
```

同一归档目录中，当天已有另一分钟驱动写入时，采集器拒绝覆盖，要求使用独立 `ETF_BURST_DIR`。不要让两个采集进程写同一缓存。并行对账本身在一个采集器中完成，不需要为了对账再开一个采集器。

## 对账和数据质量

事件 JSON 的 `tick_monitor` 和网页“Tick 与供应商 bar 对账”展示：

- 实际正式分钟驱动 `minute_driver`；已比较分钟格数 `compared`；金额差异总数 `mismatched`。
- 差异明细 `differences` 仅保留最新 20 条，完整差异总数仍保留；容差为 `max(0.01元, abs(provider_amount) × 1e-9)`。
- Tick 缺口、供应商补齐量、未补齐量及迟到/重复/累计回退拒绝数。缺口含采集器启动前未收到 Tick 的时段，不等于全部是网络丢包。
- 两个检测器的事件数，以及在双方共同已完成分钟内的事件 ID/等级差异 `event_mismatches`，明细保留最新 20 条，避免正常 2 秒封闭时差直接冒充漏报。Tick 检测器可能使用已标记的 bar 补齐，不能把这些补齐分钟当成独立 Tick 对账样本。

出现金额差异时记录差异，不自动覆盖本地封闭分钟，不倒改已发出的事件。Tick 模式中的 bar 补齐事件保留 `recovered` 标记并遵循原有“不补播”规则。

## Tick 数据回放

### 单日复盘命令

Windows 从项目根目录运行。默认回放配置里的全部 ETF，`--symbols` 可缩小范围，尤其适合先验证权限和额度。以下示例只回放 510050 及其对应的 IH 四期限合约。

```powershell
& .\scripts\python-backend.ps1 -Mode day-replay -Arguments @(
  '--day=2026-10-21', '--source=rqdata', '--symbols', '510050.SH')
```

跨平台已配置 RQData 的环境可执行 `python scripts/replay-burst-day.py --day=2026-10-21 --source=rqdata`。默认输出为 `.local/burst-day-replay/日期/`，与实时采集目录独立。

命令先使用兼容的当天基准缓存。显式 `--baseline` 优先，随后检查输入目录下的 `baseline.json`、此前生成的本地基准、实时采集目录的 `baselines/日期.json`。日期、标的、P 分位和规则版本必须匹配。RQData 模式找不到兼容基准时，会自动取目标日前 60 个交易日的 ETF 分钟成交额和日成交额，并调用与盘中相同的算法生成 20/60 日同窗分位数和全天中位数。目标日不会进入基准。有效日样本数不足时保留对应参考缺口，缺少可用基准的标的会明确报错。

联网模式用实际挂牌合约取数，只请求指定日期和所需字段。基准在取当日 Tick 前完成；Tick 分标的写入 `inputs/etf/` 和 `inputs/futures/`。若额度或网络中途阻断，保留已下载文件，并报告失败的接口和异常类型。额度恢复后用**同一条命令和同一输出目录**续跑，不重新请求已缓存的数据。可用 `--symbols` 先做小样本。脚本不会循环重试额度错误。

已有当天 Tick 时，用 `--input-dir` 指向文件目录。仍可让 RQData 自动补前序基准。若要求完全离线，加 `--offline` 并提供兼容基准，或在目录中放入 `baseline.json`。合并 CSV 或按标的分文件均可：

| 文件 | 必需字段 |
| --- | --- |
| `etf.csv` 或 `etf/标的.csv` | `symbol,datetime,last,total_turnover`。可选 `volume` 为日累计股数。 |
| `futures.csv` 或 `futures/合约.csv` | `symbol,datetime,last,total_turnover,volume,open_interest,b1,a1`。成交额单位元，`volume` 为当日累计手数，买卖一无效时留空。 |
| `contracts.json` | `{"date":"2026-10-21","products":{"IH":["IH2611","IH2612","IH2703","IH2706"]}}`。实际挂牌合约按到期顺序排列。 |

```powershell
& .\scripts\python-backend.ps1 -Mode day-replay -Arguments @(
  '--day=2026-10-21', '--source=rqdata', '--offline',
  '--input-dir=.local/burst-day-replay/2026-10-21/inputs',
  '--symbols', '510050.SH', '--out=.local/ih-replay-offline')
```

默认 `--clock=market` 按交易所行情时间重建。若两类文件都包含带时区的 `received_at`，可用 `--clock=received` 按记录接收顺序处理迟到数据。历史 RQData Tick 不带实际接收时刻，因此不能复现生产推送延迟。单日 Tick 模式复用正式判定公式，但底层分钟额来自 Tick 聚合；逐条复刻默认供应商分钟告警还需要当时的分钟推送及补数记录。期货分类继续是盘口快照估算。现货基差、ETF IOPV、盘口等辅助证据如需原样还原，还需对应数据及接收顺序。

分钟内候选使用正式分钟基准。30/60 秒持续性候选另需此前的秒级基准，命令会读取兼容缓存，也可用 `--tick-factor-baseline` 指定。缺少时仍完成分钟复盘，归档标明秒级基准未启用。需要秒级复盘时，可用已有 `tick-baseline` 命令按目标日构建。该步骤需要历史 Tick，数据用量高于分钟基准。

输出包括 `replay/日期.json` 和 `journals/日期.sqlite3`。JSON 保存分钟覆盖、事件、候选、每次确认的期货分类及合约明细。SQLite 保存正式命中、相关期货快照和每次期货判断。运行后把网页进程的 `ETF_BURST_DIR` 指向该复盘输出目录，即可在 ETF 异动雷达选择日期并拖动回放时点，切换期货金额字段。网页在窗口确认并且期货计算可用之后才显示该窗口证据。

RQData 联网复盘另取目标日和上一交易日的期末份额、单位净值及折算信息，沿用日度申赎估算口径。原始记录保存到 `inputs/fund-flow.json`。离线复盘可把该文件随 Tick 输入目录一并传入。归档 `daily_flow` 记录每只标的的 `flow_cny`、缺数原因、有效覆盖和完整篮子的 `net_flow_cny`，金额单位为元。部分标的缺数时，篮子净额及其与异动成交额的比值留空。雷达回放在 15:00 或更晚显示盘后归属结果，供复盘对照。

「历史资金」里的主动成交与日末净申赎对照使用独立的标的日专题归档。它采用 ETF 盘口中点灰区口径，单日雷达的期货方向证据使用上文的触及盘口规则。两个界面的金额粒度和输入分别见[对照数据口径](flow-methodology.md#主动成交与净申赎对照)及[导入操作](../operations/runbook.md#35-日度主动成交与申赎对照)。

**DDB 待办**。命令预留 `--source=ddb`。目前缺少完整 ETF 和股指期货 Tick 接口，选择 DDB 会明确报未接入。接入时还需对齐交易所时区、接收时间、累积成交额/成交量、持仓量、买卖一价、历史分钟/日基准及当日挂牌合约名单。

`burst-replay --burst-input` 保留原成交额分钟导入；输入额外含 `ticks` 时使用同一个 Tick 聚合器重放。`1m`/`1d` 仍用于构造截至前一交易日的基准，不能省略历史样本而冒充基准充分。

```json
{
  "schema_version": 2,
  "metric": "turnover",
  "unit": "CNY",
  "1m": [],
  "1d": [],
  "ticks": [
    ["510050.SH", "2026-11-13T09:30:58+08:00", "2026-11-13T09:30:58.100+08:00", 1.1, 1000000]
  ]
}
```

五列依次为代码、市场时间、接收时间、最新价、日累计成交额。时间必须包含时区；输入必须按接收顺序保存，不按市场时间重排迟到数据。上例只是结构示意，缺历史和完整当日 Tick，不能用于完整性验收。

```powershell
& .\scripts\python-backend.ps1 -Mode burst-replay -Arguments @(
  '--burst-input=.local/turnover-ticks.json', '--end=2026-11-13',
  '--burst-dir=.local/tick-replay', '--burst-config=.local/etf-burst-tick.json')
```

输出仍为 `replay/YYYY-MM-DD.json`，含正式事件、接收覆盖、拒绝统计和独立 `candidate_history`。网页按回放时点过滤历史 Tick 候选；普通分钟回放不会伪造分钟内候选，回放不播报。正式事件展示仍以分钟为粒度，不能由此推断真实通知到达秒数。

当前采集器将 Tick、供应商分钟、候选、正式命中、数据缺口和回补追加至私有 SQLite 日志，包含行情及接收时间。历史供应商 Tick 仍没有当时本机接收时间；模拟接收场景不代表实盘时延验收。旧回放默认 `legacy-right` 保持原口径；新采集数据回放使用 `--tick-boundary=provider-v2`。

## 测试证据及切换条件

上一版（2026-11-19）回归：Python **55 项通过**，Node **95 项通过**；以下合成验收作为历史证据保留。2026-11-21 的实现和真实历史验证见下节。

- 自动回归覆盖：累计差分、整分钟边界、2 秒封闭、10 秒陈旧边界、午休、指数无成交额、重复/乱序/迟到/回退、候选不改正式状态、Tick 单独确认、供应商补齐、防止同日跨驱动覆盖、原分钟回放及 Tick CLI。
- 同一组整数分钟输入下，Tick 回放与原 bar 检测器的正式事件、升级和中位数影子结果逐项相同。
- 本地缓存三日、当前篮子重叠的 16 只 ETF：把原分钟额构造成累计快照再重放，正式事件分别 **20 / 31 / 7**，按事件 ID 对齐后的首报分钟、最新分钟、等级、峰值窗口一致。多标的同一时刻触发的数组顺序不作为规则差异。证据在 `.local/tick-driver-validation/results.json`。
- 上述累计快照是从分钟数据**合成**，不是实际历史 Tick；当前篮子另外 4 只没有补齐。本次证据不足以证明真实 Tick 和供应商分钟完全一致。
- 浏览器验收检查：候选可见、正式事件数不因候选增加、开启语音后候选不额外播报，以及九张原图、SSE 回退、历史回放。

生产切换前应取得真实 Tick 与供应商 bar 的同日记录，覆盖开盘、午休、重连及收盘，检查逐只逐分钟金额、候选与正式首报时刻、事件等级与漏报。先解释所有差异，再决定是否启用 `minute_driver: "tick"`；没有配置为自动切换，也没有假定已完成真实账户验收。

## 2026-11-21：金额累计、日志和秒级候选

### 确认金额与日末申赎

`BurstDay` 保留二级及以上实际命中窗口的分钟并集。相同 ETF、相同分钟只累计一次，不累加重叠 5/10 分钟窗口，也不把事件间隔中的普通分钟纳入。`accounting.minutes` 每行依次是 ETF、分钟、实际成交额、历史同分钟 P 分位参考、首次确认分钟、接收时间；金额单位元。`gross` 为并集成交额，`positive_excess` 为逐分钟正超额之和。参考缺失时超额保持缺失。

UI 展示去重成交额、正超额成交额、同篮子同日净申赎和量级比。日末申赎为盘后归属值，不参与盘中信号；日期、覆盖成员或数据不完整时不计算比值。旧归档没有 `accounting` 字段时显示缺失。回放按确认时间过滤；有接收时间的归档还按接收时间过滤，避免提前看见迟到结果。

正式命中日志还记录相对当日此前20个连续分钟的原始环比、按历史同分钟 P 分位归一后的环比。当前分钟不进入前窗；午后重置；前窗不够20分钟或存在缺数时不计算。环比仅作为证据展示，不改变正式门槛。

### 秒级持续性候选

`tick-persistence-v1` 在每个有效 Tick 到达时，推进已结束的5秒桶，更新30/60秒窗：

| 条件 | 30秒 | 60秒 |
| --- | ---: | ---: |
| 同窗额 / max(20日P分位,60日P分位) | ≥5 | ≥3 |
| 5秒桶同窗额比≥3的比例 | ≥4/6 | ≥9/12 |
| 窗口额 / max(20日全天中位数,60日全天中位数) | ≥1% | ≥2% |

沿用配置 `amount_window_quantile`，默认0.75；样本须至少19/20、55/60日。5秒桶端点新鲜度6秒；午休不跨窗，累计回退、缺数或无效参考不会补零。30/60秒窗不必等待整分钟，但本版仍是5秒桶推进，不是逐笔成交检测。

秒级候选单独写 `tick_candidates`，不写正式事件、不播报，不自动升级或调整门槛。基准缺失、过期或分位不兼容时，仅暂停秒级候选，原有分钟确认继续运行；界面显示基准覆盖数量。

### 盘前准备与启动

Windows 在项目根目录运行，参数显式通过 `-Arguments` 传入：

```powershell
# 示例目标交易日；后续每个交易日需准备对应日期，不创建本机计划任务。
& .\scripts\python-backend.ps1 -Mode tick-baseline -Arguments @('--day=2026-11-23')
& .\scripts\python-backend.ps1 -Mode live -Arguments @('--watch')
# 另开终端，沿用项目原有数据模式和雷达配置
& .\scripts\python-backend.ps1 -Mode web
```

跨平台或腾讯云的已配置 RQData 环境：

```text
python scripts/prepare-tick-baseline.py --day=2026-11-23
python -m etf_backend.collect live --watch
python -m uvicorn etf_backend.web:app --host 127.0.0.1 --port 8080
```

准备命令读取 `ETF_BURST_CONFIG`、`ETF_BURST_DIR`，输出 `tick-baselines/目标日.json`；成员和分位来自同一配置，基准只取目标日前60个交易日。应在采集器创建当天会话**之前**完成准备；盘中补文件需重启采集器重新加载。参数改变后重新准备并使用隔离目录验收。凭据沿用本地保护配置，不写入命令或仓库。

离线开发可用 `--input-dir=.local/intraday-research-20261121 --symbols 510300.SH 588000.SH 159915.SZ --out=.local/tick-upgrade/baselines`；输入目录必须有真实历史 Tick 和交易日历。该缓存只包含三只 Tick，不能用于声称20只全部离线验收。

生产调度由目标 Windows 任务计划程序或云端任务系统配置：在交易日盘前依次准备当日基准、检查成功退出和覆盖、启动采集器；失败时报警并保留原分钟监控。不要把周一至周五等同于交易日，不要在失败后把昨日基准改名充当今日文件。本项目未安装或启用本机定时任务。

### 日志与复盘

日志位于 `ETF_BURST_DIR/journals/YYYY-MM-DD.sqlite3`，私有、不随源码发布。每次会话记录驱动、规则、分位、基准截止日和摘要；记录类型包括 `session/tick/bar/candidate/candidate_removed/formal/data_gap/recovery/end`。`end` 是11分钟以上无新命中的非活跃标记。原始行情按接收顺序保留，包括被聚合器拒绝的 Tick，记录 `accepted` 供排查。

SQLite 写入按约1秒的 UI 发布周期批量提交；异常退出可能损失尚未提交的最后一批，不能宣称逐 Tick 同步持久化。记录以稳定键去重，读取使用只读连接和游标分页；Windows 每批关闭连接，不长期占用文件句柄。

```text
GET /api/etf-burst/journal?date=2026-11-23&kind=formal&limit=200&after=0
```

响应 `next_after` 用于下一页，可选 `symbol`；`limit` 为1至1000。此接口仅限启用雷达的真实数据模式，保持原部署访问边界；原始行情日志不得直接开放给公众小程序用户。

```powershell
python scripts/summarize-burst-journal.py data/private/etf-burst/journals/2026-11-23.sqlite3
```

统计按 ETF 事件的首次二级确认时间生成10分钟分布，标出回补事件。不能当作交易主体的操作次数；同一行动可能对应多个 ETF 事件。日志为日分区，由生产部署按授权范围保留和备份，迁移时应先停止写入并完整备份数据库及仍存在的 WAL 文件；项目不自动清理历史日志。

新 Tick 回放可附加：

```text
--tick-boundary=provider-v2 --tick-factor-baseline=.local/tick-upgrade/baselines/2026-11-20.json
```

仍需传入带真实接收时间的 Tick 输入及此前分钟/日线基准。秒级候选保存至 `tick_candidate_history`；普通分钟回放只能还原正式分钟事件，不能伪造秒级候选。
